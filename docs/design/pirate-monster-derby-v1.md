# 海賊魔獣ダービー v1 企画仕様書

## 結論

建設予定地Bへ、4属性のHippogriffが9.3mの直線を走る「盤上型レース」を配置する。プレイヤーは1・3・5枚から賭け金を選び、1〜4号へ投票する。1人でも開始でき、同じXRiftインスタンスにいる複数人は同じラウンドと着順を観戦する。

実装はまだ開始しない。本資料、YAML、JSON、三面図、コンセプト画像のレビュー後に灰色箱PoCへ進む。

## なぜ実寸競馬場にしないか

建設予定地Bは12m×10mである。ここへ実寸の馬、観客席、操作UIを同居させると、現在のワールドで改善してきた「狭い通路」「3D UIが対象物を隠す」という問題が再発する。

そこで、競走路を10.4m×5.0mの盤として少し持ち上げ、接近側に奥行1.4m以上の連続歩行帯と低い観戦レールを置く。プレイヤーは競走路へ座らず、自由に立ち位置を変えて観戦する。カメラ固定、pointer lock、ESC操作は要求しない。

## 体験の芯

1ラウンドは投票開始から次ラウンドまで約45秒。最初の投票が入るまでは待機し、投票後20秒で締め切る。急いで遊びたい場合は、受付開始から7秒が経過し、投票者が1人以上いるときだけGM横の出走レバーで残り時間を3秒へ短縮できる。最初の投票者が即座に締め切ることはできない。

賭けは操作台だけで完結する。

1. 「1枚・3枚・5枚」を選択
2. 「1号〜4号」を選択
3. 「この内容で投票」で確定
4. 締切前なら「取消」で全額返金
5. 12秒の競走を観戦
6. 1着は賭け金込み3倍、2着は賭け金返還

4体は毎回均等な25%の勝率とし、「先行・持久・追込・波乱」は見た目の走行曲線だけを変える。表示していない能力差や隠し補正は入れない。

## 配当設計

総取りプールではなく固定配当にする。これにより、参加者が1人でもゲームが成立し、他プレイヤーの残高を直接減らす処理も不要になる。

| 着順 | 払戻総額 | 3枚賭けの例 |
|---:|---:|---:|
| 1着 | 賭け金×3 | 9枚 |
| 2着 | 賭け金×1 | 3枚 |
| 3着 | 0 | 0枚 |
| 4着 | 0 | 0枚 |

均等勝率の場合、理論払戻率は `25%×3 + 25%×1 = 100%`。ワールド内の遊技コインを過度に減らさず、1着の高揚感も残せる。残高0枚の救済は既存どおり受付で10枚を受け取る方式で、自動配布しない。

## 同期と精算

同一インスタンス内のラウンドは `useInstanceState` で共有し、World Storageは各プレイヤーの永続コインに使う。勝敗はレース開始時にround seedから一度だけ着順を生成し、その着順へ収束する走行曲線を全クライアントで再生する。フレームごとに勝敗抽選を行わない。

既知の制約として、コインの加算とInstance Stateの精算済み記録を一つのトランザクションにはできない。v1では賭け金を最大5枚に制限し、同一roundIdの二重実行防止、精算中の操作禁止、精算済みユーザー一覧を組み合わせる。再接続、同時タブ、精算途中の切断は明示的なQA項目にする。

投票確定では先にコインを減算し、その後にENTRYを登録する。登録に失敗した場合は補償返金する。厳密な金融トランザクションではなく、最大損失を5枚へ限定したワールド内遊技として設計する。

## 3D UI方針

大型のゲーム画面は出さない。既存コインHUDへ「未投票」「投票済3枚 / 2号」「1着 払戻9枚」の1行だけを追加する。

賭け金、レーン、確定、取消は傾斜した3D操作台へ配置する。結果はコース右奥の高さ3.6m以下の順位塔で表示し、主要視点から競走路に重ならない位置へ置く。

操作は左から「賭け金」「レーン」「決定」の順に並べる。現在の選択内容は操作盤上部へ常時表示し、確定後は賭け金とレーンを無効化する。取消はENTRY中だけ有効とする。詳細は `pirate-monster-derby-v1-console-ui.svg` を原本とする。

## アニメーション方針

Hippogriffの確認済みクリップは `idle / hit / attack`。専用走行クリップがないため、次を手続き生成する。

- レース進行位置
- 最大0.08mの上下動
- 最大4度のロール
- 最大6度のピッチ
- 脚質ごとの加減速
- 終盤の羽ばたき頻度

既存クリップは待機、号砲への反応、ゴール後の喜怒へ限定して使う。カメラシェイクは使わない。

GMは受付中と結果表示中に操作台前のプレイヤーを向き、競走中だけ首と上体をコースへ向ける。常時コースを向かせてプレイヤーへ背を向ける状態を禁止する。

- 4体を超える同時レーサー
