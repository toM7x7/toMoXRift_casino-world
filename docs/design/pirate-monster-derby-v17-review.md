# 海賊魔獣ダービー v17 観覧方式再検討

## 結論

奥へ伸びるv16直線は不採用とする。現行`xrift.json`のカメラ遠クリップは80mだが、v16のゴールはB中心から約91m先にあり、ゴール側が小さいだけでなく描画範囲外になる可能性がある。

本命は、既存Bを8人対応の回遊型投票所へ変更し、東へ短く歩いた先に独立した展望デッキを設け、デッキと平行に60mの遠景直線を置く案とする。スタートとゴールは観覧柵中央から等距離で、どちらも37.2m。プレイヤーは左右へ約54度ずつ視線を振るだけで、発走と決着を同じ大きさで確認できる。

遊技村外周を一周する案も成立する。ただし、反対側区間が床・BJ/MJ・受付・高さ7.6mの運命盤に隠れるため、「常にレースが見える」より「一度見失って戻ってくる興奮」を優先する別モード向きである。

## B1：8人対応の回遊型投票所

既存B区画12×10mは競走路を置かず、投票だけを行う。

- 中央に直径4.2mの八角形投票台
- 半径3.0mに8つのENTRYパッド
- 投票台の外側に最小1.2mの環状通路
- 南入口、東出口を分離し、人の逆流を減らす
- 椅子は使わず、立ったまま号数・1/3/5枚・確定を操作
- 確定後はENTRYパッドから離れても投票を保持
- 最大8人。未参加者とNPC観客は人数枠を消費しない

8台の大型コンソールを並べると区画が再び狭くなるため、操作部は八角台の各辺へ埋め込む。各辺は一人分の小さな3D操作面で、中央上部にはラウンド残り時間と投票済人数だけを表示する。

## B2：投票所から展望デッキまで

- B東端から幅4m・長さ3mの短いランプ
- ランプ勾配1:5、床高0mから0.6mへ上がる
- 展望デッキ：8×18m、床高0.6m、中心`[30, 0.6, -13]`
- デッキ東側に8つの観覧マーカー。間隔1.8m
- 固定席・カメラ固定・pointer lockなし
- 北・南・東に1.1m手すり、西はランプ開口だけを残す
- 離席操作は不要。自由に投票所へ戻れる

デッキは「着席ゲーム」ではなく自由観戦空間とする。ぐるぐる見回しても操作状態を失わず、投票後の個人状態はHUDの1行に保持する。

## 案P：デッキと平行な60m直線（本命）

コースは東側の遠景に南北方向で置く。

- コース中心x=56m
- スタートz=-43m、ゴールz=17m、全長60m
- 幅11.2m、4レーン
- デッキ東柵からコース中心まで約22m
- 観覧柵中央からスタート・ゴールまで各37.2m
- 8つの観覧マーカー端から反対側端点まで最大42.5m
- コース基準高0.2m、観覧眼高約2.2m、中央への俯角約5.2度
- 視線角：中央から左右約54度、合計約108度
- レース時間16〜21秒
- 非歩行・コライダーなし
- 既存カメラfar=80を変更しない

発走門とゴール門は同じ高さ4.8m・幅13mとし、色、旗、縦光柱で端点を示す。プレイヤーが中央を向いたまま両端を同時に画面へ収めることは要求しない。通常FOV62度に対し、左右へ一度ずつ見れば確認できる構成とする。

コース中央には高さ2.0mの風橋、前後に小さな加速坂と谷を置く。横から少し見下ろすため、ジャンプ弧と抜きつ抜かれつが奥行き直線より読みやすい。

## 案L：遊技村外周1周

コア56×42mの外側に4レーンの角丸ループを置く。

- 中心線外形68×54m、角半径9m
- 1周約228.5m
- 4レーン総幅11.2m
- コース高0.4m、展望デッキ床高1.8m
- スタートとゴールは東側の同一ライン
- レース時間30〜38秒

利点は、村全体がレース会場になり、スタートとゴールが同じ場所なので決着を見失わないこと。欠点は、反対側の直線が遊技床とオブジェクトに遮られ、現在のカメラfar=80でも最遠外周がほぼ限界になること。

外周案を採用する場合は、次が追加条件になる。

- farを100〜110へ変更して描画負荷を再計測
- 反対側区間を8〜12秒見失うことを演出として許容
- 手元進行レールまたは頭上の区間旗を必須化
- 外周トラックと既存床のコライダー境界を全周検証

## 比較

| 評価 | 平行60m直線 | 外周228mループ |
|---|---:|---:|
| スタート・ゴール視認 | 5 | 5 |
| レース中の継続視認 | 5 | 2 |
| 長距離感 | 4 | 5 |
| 遊技村との一体感 | 3 | 5 |
| 現行far=80との整合 | 5 | 2 |
| 実装・コライダー安全性 | 4 | 2 |
| 8人観戦の分かりやすさ | 5 | 3 |

初回実装は平行60m直線を推奨する。外周ループは、平行コースで8人同期・投票・決済・観覧導線が安定した後に、イベントレースとして再評価する。

## 8人同期

ラウンド状態は同一XRiftインスタンス内で共有する。`useWorldStorage`は財布の永続化だけに使い、8人の投票、締切、seed、発走時刻、結果はインスタンス状態に置く。

- 参加上限8
- 参加者IDの重複登録禁止
- 確定時に賭け金を一度だけ差引
- 締切前は取消・全額返金
- 発走後の切断は結果確定時に冪等精算
- レーサー位置はseedと発走時刻から各端末で再生し、毎フレーム同期しない

## 実装ゲート

1. 8人投票所と環状通路のグレーボックス
2. ランプ、展望デッキ、手すり、8観覧マーカーのコライダーQA
3. 平行60mコースを4色キューブで走らせ、左右端の視認性を確認
4. 1/4/8人の同一インスタンス投票・締切・精算テスト
5. Hippogriffと区間演出を投入
6. 外周ループは別レビュー・別feature gate

## 承認条件

- 8人が投票台の周囲へ立っても、環状通路1.2mを塞がない
- 投票所から展望デッキまで迷わず10秒以内
- 中央観覧位置からスタートとゴールの見かけ高さが同等
- スタート・ゴール・全レーサーがfar=80以内
- 発走中に大型2D UIがレース場へ重ならない
- 技術PASSと視覚PASSを別々に判定

今回は設計レビューのみで、実装・アップロードは行わない。
