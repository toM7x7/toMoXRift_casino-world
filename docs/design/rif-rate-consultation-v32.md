# RIF管理者向け：カジノコイン相互交換の相談案 v32

## まず共有したい結論

現在このワールドでは、RIFからカジノコインへの一方向交換だけを提供しています。相互交換はまだ実装せず、次のルール案について先に相談したいです。

```text
提案レート：1 RIF ＝ 50カジノコイン
入金：1 RIF → 換金可能なカジノコイン50枚
出金：換金可能なカジノコイン50枚 → 1 RIF
交換方向によってレートは変えない
```

50という数字は手数料ではなく、遊技で1枚・3枚・5枚の掛け金を扱いやすくするための単位変更です。経済を厳しくする仕組みは、方向別の不透明なレート差ではなく、換金可能残高、出金上限、RIF準備金、各ゲームのハウスエッジで設けます。

## カジノコインを2種類に分ける案

| 種類 | 入手経路 | 遊技 | RIFへ出金 |
| --- | --- | --- | --- |
| 換金可能コイン | RIFを交換所へ入金 | 可能 | 50枚単位で可能 |
| 遊技用ボーナス | 既存残高、救済10枚、運営配布、β報酬 | 可能 | 不可 |

ボーナスを賭けて得た払戻はボーナスへ戻し、換金可能コインを賭けた払戻だけを換金可能にします。これにより、無料配布10枚を増やしてRIFへ戻す経路を防ぎます。

旧カジノ残高は50倍せず、その枚数のまま遊技用ボーナスへ移す想定です。過去に稼ぎやすかった残高がRIFへ流出することを防ぎます。

## 出金の暫定制限案

| 項目 | β開始値 |
| --- | ---: |
| 最低出金 | 50枚＝1 RIF |
| 1回上限 | 150枚＝3 RIF |
| 1日上限 | 250枚＝5 RIF |
| 交換手数料 | 0% |

例：換金可能残高が138枚なら、100枚を2 RIFへ出金でき、38枚が残ります。ボーナス残高が1,000枚あっても、それだけでは出金できません。

## RIF準備金

このワールドから出金できるRIF総額は、交換所が過去に受け取ったRIFの範囲内に制限する案です。

```text
出金可能RIF ＝ RIF入金累計 − RIF出金累計 − 処理中の出金予約
```

同一ユーザーが複数インスタンスへ同時参加できない仕様のため、同一人物の二重出金リスクは小さいと認識しています。一方、別ユーザーからの同時出金はあり得るため、共有準備金の原子的な予約と、通信失敗時の復旧記録は必要です。

## 遊技側の考え方

- ブラックジャック：現実寄りのディーラールール、理論RTPはシミュレーション上およそ94.8%。
- 船長の運命盤：掛け金によりRTP 87.5〜92.5%。
- 海賊魔獣ダービー：掛け金1／3／5枚のRTPを75.0%／91.7%／95.0%へ見直し、全掛け金で100%未満にする。
- アニマルじゃらβ：当面無料、コイン増減なし。ルールと操作性の検証後に93〜95%を目標に調整。
- 麻雀／将来の動物紋章ダイス：ルール監査が終わるまで換金可能コインの対象外。

換金可能コインを使えるゲームは、RTPと二重精算防止を確認できたものから段階的に開放します。

## RIF管理者へ確認したいこと

1. `1 RIF＝50カジノコイン`の固定・両方向同率という考え方に問題がないか。
2. 世界単位で「入金されたRIF以内だけ出金可能」とする準備金方式でよいか。
3. 1回3 RIF、1日5 RIFという初期限度額が適切か。
4. RIF付与APIに世界単位・ユーザー単位の上限を設ける必要があるか。
5. `worldId + clientTransactionId`による冪等付与を正式な復旧方法としてよいか。
6. 出金履歴に必要な`reason`、ゲーム名、ラウンドID、元コイン区分などのmetadata項目。
7. レート変更時の告知期間、旧レートの扱い、管理者同士の合意手順。

- RIFの実付与処理

合意後に、管理区画の準備金監視、pending復旧、少額上限を含むβ実装を別リリースで行う想定です。
