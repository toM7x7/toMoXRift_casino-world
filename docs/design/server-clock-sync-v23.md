# Neon Casino Club サーバー時計同期 v23

実装日: 2026-08-15

## 目的

船長の運命盤と海賊魔獣ダービーについて、端末の `Date.now()` やページを開いてからのローカル経過時間ではなく、インスタンス共通の `useServerClock({ require: 'motion' })` を描画時刻に使う。

## 正本

- ラウンド状態、BET、当選色、勝者: `useInstanceState`
- 開始時刻 `startedAt`: `useServerClock().now()` で作ったサーバー時刻エポック
- カウントダウン、回転角、走行位置、揺れ、紹介、結果保持: `serverNow - startedAt` の関数
- 払戻: 共有された `resultIndex` とユーザー自身のBETから計算

`useServerClock` は表示タイミングを揃えるために使い、早押しやゴールの勝敗裁定には使わない。ダービーの勝者はラウンド開始時に共有状態へ確定している。

## 運命盤

- セッションキーを `casino.fate-wheel.round.v4` へ更新。
- 回転角を、ラウンドID、当選区画、開始時刻、サーバー現在時刻から毎フレーム再計算。
- 過去フレームの回転角を積算しないため、途中参加と時刻ジャンプの次フレームで自己回復。
- 3秒前カウントダウンSE、回転開始SE、払戻、結果保持終了を同じサーバー期限で予約。

## ダービー

- セッションキーを `casino.pirate-monster-derby.round.v4` へ更新。
- 4体の走行距離、上下動、左右傾きをサーバー時刻から毎フレーム再計算。
- Hippogriffのidleアニメーションミキサーもサーバー時刻の位相へ合わせる。
- 出走紹介、3秒前カウントダウン、発走SE、実況順位、払戻、待機復帰をサーバー期限へ統一。

## 時刻ジャンプと途中参加

- 位置・角度は時刻の絶対関数なので `timeJumpCount` 後も次フレームで復帰する。
- SEと期限処理は最大1秒ごとにサーバー残時間を再評価する。
- 開始後250msを超えて参加した端末では、頭から鳴らすと不自然な開始SEを再生しない。
- ローカル開発では `XRiftProvider.serverClockImplementation` に同期済みフェイク時計を注入。

## 共通コインとの境界

共通コイン連携でも `useServerClock` を残高や取引順序の正本にはしない。

使ってよいもの:

- レート見積の残り時間表示
- 交換受付の締切カウントダウン
- 全員共通キャンペーンの開始演出
- 共同建設の開業演出

使わないもの:

- 二重支払防止
- 取引の順序保証
- 残高の確定
- 交換成立の裁定
- ユーザー間送金の競合解決

それらは外部サーバーの取引ID、冪等キー、台帳、サーバー側時刻で裁定する。
